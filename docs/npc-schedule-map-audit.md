# NPC 实际地图日程审计

## 运行方式

使用 Java 21，提供一个已关闭的存档或一致的存档备份：

```sh
python3 tools/npc/run_schedule_audit.py --save /path/to/offline-save
```

脚本检查存档锁，复制到 `build/npc-schedule-audits/<时间>/world`，只在副本启动无窗口服务端。不会打开客户端，也不会修改源存档。默认仅监听 `127.0.0.1:25575`；端口占用时用 `--port` 指定其他端口。

运行时不要同时启动其他 Gradle 编译任务，开发启动共享同一个编译输出目录。

每次完整执行冬季第 1、2 天的 06:00–次日 02:00，共 40,000 个正常模拟 tick，另有 200 tick 启动准备。使用原生 tick sprint 缩短墙钟时间，日程时钟仍是 1,000 tick/游戏小时，NPC 不能获得额外移动时间。无玩家时仅补齐未被强制加载区块自然执行的 NPC tick，不重复 tick；无人暂停与 Joja/矿井居民生成只在显式测试开关下解除。

日程使用正式选择器、队列、移动服务、碰撞、建筑传送和跨天处理。报告记录实际实例、应执行节点、确认到站节点、最近可达落点、持续停滞、重复实例、室内错位及柜台位置偏差。日程通过传送门后仍必须完成最终站点，不能将“到了门口”当作完成。

- `report.json`：逐 NPC 的节点与异常证据。
- `server.log`：完整服务端日志。
- 返回码 `0` 才表示审计完成且没有报告异常；`1` 表示行为异常或缺失，`2` 表示启动/执行失败。Gradle 的 `BUILD SUCCESSFUL` 单独不能代表日程通过。
- 总计 41 个已实现角色，普通日期应观测到 40 个；州长只出现在节日，本场景明确排除。驻店角色没有移动日程，按实际出现情况单列。

本场景验证实际地图中的冬季两天日程与柜台坐标，不代表其他季节、节庆、婚后分支、玩家实时交互或客户端动画已经全部验收。报告不上传存档。

## 本次修复的共同约束

1. 规划器、移动器与队列保留相同的最终命名点。路线中间步骤随 NPC 所处房间变化，不再因此重建当前计划。
2. 日程目标保持配置高度，不能被原生导航改写到家具或屋顶上方。带高差的斜向边改用可实际行走的正交台阶路径。
3. 实际到站产生绑定实体和位置的完成记录；物理 tick 中临时的 `onGround=false` 不再让下一站永远等不到。外部位移后旧完成记录失效。
4. 完整路径与分段续接耗尽后，日程才采用已验证、实际走到的可站立端点；同一室内区域的检查贯穿全过程。剧情脚本仍保留其原有精确行走约束。
5. 对身体已经嵌入方块的起点，只在附近同一区域内寻找有地面支撑的脱困点；不会直接把普通日程角色搬到远处目的地。
6. 行进中的日程 NPC 不互相施加推力造成窄路死锁；到站占位仍等待或就近站立，玩家碰撞不受影响。
7. 柜台点明确配置 `arrival: "exact_work"`，到目的房间后精确对齐并保持工作坐标，允许跨过工作位碰撞。其他点默认采用最近可达策略。未知 `arrival` 值会被数据校验拒绝。

## 定向回归

```sh
./gradlew classes
./gradlew runGameTestServer -PgameTestNamespaces=stardewcraft_npc_runtime
```

必须检查日志中的 `All N required tests passed`。测试覆盖精确工作位、目标高度、不可达端点、到站后推进、门/台阶/人群，以及现有日程与活动用例；它们补充实际地图审计，不能代替它。

## 2026-09-20 验证记录

实际存档副本完成冬季两天：40 个角色已观测，280/280 个日程节点完成，其中 34 个曾采用最近可达兜底；柜台偏位、错室内、持续停滞和重复实例均为 0 项审计异常。96 项必需 NPC GameTest 全部通过，包括到位后被挤动的柜台保持检查。就近完成不等于精确抵达原坐标。
