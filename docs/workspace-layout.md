# 工作区、母本与 Git 收录

## 两个开发入口

`main` 维护 Minecraft 1.21.1 / NeoForge，并在 `fabric/` 维护共享源码的 Fabric 子项目；`mc1.20.1-forge` 维护 Minecraft 1.20.1 / Forge。
本机分别使用 `StardewCraft` 与 `StardewCraft-1.20.1-Forge-bulk`。当前不重命名入口，不为每次发布长期保留完整工程副本。
两个分支各自保有构建输入；不能让任一版本通过绝对路径依赖另一工作树或本机研究目录。
共同改动按任务对照并移植，保留加载器 API、资源格式与已约定豁免；不能把整个分支互相覆盖。

## 文件职责

| 位置 | 职责 | Git 收录原则 |
| --- | --- | --- |
| `src/main`、`gradle`、`compatibility`、例程 | 正式源码、运行资源、可移植构建与验证 | 维护必要内容；验证不能读取本机研究资料 |
| `assets-src/npc`、Sebastian 电脑母本 | 已注册的自动编译输入 | 必需源和工具必须随版本保存 |
| `assets-src/authoring.json` 登记的装饰母本 | 稳定编辑源，手动导出到正式资源 | 逐族核实来源、依赖、消费者后明确放行 |
| 其他 `assets-src`、`建模试作` | 尚未归位或未核实分发范围的母本与制作过程 | 暂留本地；ignored 不等于垃圾或可删除 |
| `docs`、`scripts`、`tools` | 维护规则、导出与验证工具，另含本地研究 | 精确白名单，不整包开放 |
| `源文件`、`bb学习` | 原版研究与案例资料 | 本地保留，不推定公开许可 |
| `本地资料/历史归档` | 已退役环境、历史源、制作记录和恢复包 | 仅本地；Git 排除不是云端备份 |
| `tmp`、`.tmp`、`run`、`build` | 临时输出、工具链、运行世界、构建结果 | 先核对实际角色；世界和翻译模型不可按名称清掉 |

`assets-src/authoring.json` 目前只覆盖快递盒和购物篮，不代表全库资产已归位或美术已验收。
NPC 等现有自动编译注册仍由各自 Gradle 文件及模型清单管理。
信箱使用稳定本地目录 `assets-src/furniture/mailbox`；公开许可未完整核实，所以不列入公开母本清单。

## 母本归位与验证

1. 以现用导出器、接入记录和运行产物确定母本，不按最大版本号猜测“最新版”。
2. 核对内嵌/外置贴图、参数、消费者和来源。先备份并验证恢复包，再归位；不覆盖另一候选或用户在改内容。
3. 同步消费者，输出先写隔离目录，与旧导出及正式产物逐文件比较。仅换入口不能改变几何、动画、资源 ID 或游戏行为。
4. 阶段源、有效制作参数、最终代表性预览和说明集中归档。历史回放脚本可能绑定当次项目 UUID，不是可盲目执行的维护工具。
5. 未来对母本做真实修改时，同步内嵌和外置纹理、正式资源及登记的输出路径，再运行检查；检查通过不等于视觉或实机验收。

这两组公开母本的只读检查与隔离导出对照不依赖第三方资料、存档、其他工作树或本地归档：

```sh
python3 scripts/check_authoring_sources.py
python3 scripts/check_authoring_sources.py --verify-exports
```

正式构建使用已提交的运行资源，不会自动执行这两个手动导出器。

## Git 与发布边界

收录范围由 `.gitignore` 精确白名单控制；新增内容还需要显式审核、提交和推送才会出现在 GitHub。
维护文档和母本收录应独立提交；功能发布另行记录对应源码与验证。
`src/test` 仍是本地开发内容，不纳入 Git；正式验证使用仓库维护的可移植检查。
发布时按仓库既有规则，在候选提交的干净独立检出中运行全部 CI，再确认远端 Actions 完成。
安装包仍从明确版本的发布目录取用，不能把过程测试 JAR 或历史恢复包当正式版本。
