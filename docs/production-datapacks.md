# 生产时间与生产规则数据包

## 可以直接发给玩家的用法

本次更新后，树液采集器可由服务端数据包配置。在 `data/stardewcraft/production/tapper.json` 写入：

```json
{"minutes": 60}
```

所有树液采集器的新周期统一为 60 游戏分钟。只想改橡树：

```json
{
  "cycles": {
    "oak": {"duration": {"minutes": 60}}
  }
}
```

修改在 `/reload` 后的下一轮生产生效，不会重置或重算正在加工的任务。服务端配置随登录和重载同步到客户端，JEI 使用同步后的普通机器时间及产量范围，Jade 读取实际加工状态。服务端与客户端都需要包含这次更新的模组版本。

完整可安装示例位于 `examples/datapacks/faster-production/`。数据包格式为 Minecraft 1.21.1 的 48。整文件夹放进世界的 `datapacks`，然后 `/reload`。

## 现有配方与新增生产配置

| 入口 | 用途 |
| --- | --- |
| `data/<namespace>/artisan/*.json` | 输入物品或标签、消耗数量、产物、产量、单条配方的分钟数（`minutes`）或「第 N 个早晨完成」（`days`，对应原版 DaysUntilReady，与 `minutes` 互斥）；保留既有格式 |
| `data/<namespace>/production/<machine>.json` | 按机器统一调整时长；补齐不需要输入配方的被动生产周期、陈酿速率、重型熔炉煤耗 |

生产配置文件的资源 ID 就是机器 ID。例如 `data/stardewcraft/production/keg.json` 对应 `stardewcraft:keg`。给本模组机器调参时不要把文件放在自定义 namespace 下，否则会对应另一台机器。

```json
{"time_multiplier": 0.5}
```

表示耗时减半。可选 `minutes` 把该机器所有配方先统一成固定分钟数，再乘 `time_multiplier`。最终正时长向上取整，至少一分钟，超出整数范围时饱和到上限。普通批量/复制/环境周期的配置在通用 cycle provider 之前应用；已有 legacy 批量 plan provider 先执行，随后应用此调时，再执行通用 cycle provider。附属模组的上下文相关 provider 仍可进一步修改或拒绝计划，JEI 无法预先模拟这类条件逻辑。

覆盖的计时设施：原有 artisan 机器（含孵化器）、重型熔炉、晶球破碎机、树液采集器、普通/高级虫箱、蜂房、太阳能板和避雷针。内置参数全部在 `src/main/resources/data/stardewcraft/production/`。孵化器在数据调时之后叠加职业时间修正。

## 被动周期

`cycles` 按名称合并。树液采集器用 `oak`、`maple`、`pine`、`mahogany`、`mystic_tree`；其他设施用 `default`。支持树 API 的附属树种可用完整树种 ID（如 `addon:rubber_tree`）提供覆盖；未提供时保留附属树的产物与周期，再应用机器调时。

```json
{
  "cycles": {
    "mahogany": {
      "output": "stardewcraft:sap",
      "min_count": 3,
      "max_count": 8,
      "duration": {"mornings": 1}
    }
  }
}
```

- `minutes`：从开始时刻经过指定的有效游戏分钟。
- `mornings`：到第 N 个早晨完成。两个单位互斥，都是正整数。
- `time_multiplier` / 根节点 `minutes` 对该周期算出的剩余时间继续生效，因此加速后的完成时刻不保证仍落在早晨。需要严格在第 N 个早晨出货时，只改 `duration.mornings`。
- 机器时钟与原版一致：一天 1600 机器分钟（白天 6:00–次日 2:00 共 1200，入睡时按 `Utility.CalculateMinutesUntilMorning` 补到早上，任何入睡时间合计都是 1600）。这是日历换算，不是可任意修改的机器平衡参数。旧版本（一天 1260）存档中正在加工的机器在首次加载时按原完成时刻（第几天、几点）换算到新时钟，并写入 `stardewcraftMachineClock` 标记，不会重复换算。
- 树液采集器默认夜数为 7/9/5/1/7；修正了旧式日序加法额外多等一夜的问题。旧任务仍按保存的截止时间结束。
- 普通/高级虫箱默认次日早晨（`mornings: 1`），产 4–5 普通/高级鱼饵；避雷针被雷击中后到次日早晨产电池；蜂房默认第 4 个早晨。
- 蜂房在此只配置周期；采收时按花朵决定蜂蜜的既有逻辑保留。晶球破碎机在此只配置分钟，产物继续走晶球掉落数据。
- 太阳能板默认保留每日结算模式；指定分钟周期、固定分钟或修改倍数后，使用按有效分钟递减的充能模式，仍受天气和天空条件约束。模式和剩余进度随方块实体存档。

## 陈酿与重型熔炉

陈酿桶配置 `aging_rates`（物品 ID → 每天推进的陈酿单位）和 `time_multiplier`。不支持根节点 `minutes`，因为它是分品质阶段的每日加工系统。默认 cheese/goat_cheese=4、mead/beer=2、pale_ale=1.66、wine=1。自定义物品也可以加入；风味葡萄酒使用 wine 的配置，附属解析器仍作为未配置物品的兜底。

```json
{
  "time_multiplier": 0.5,
  "aging_rates": {"stardewcraft:cheese": 6}
}
```

已装入桶的 `agingRate` 是当批快照，重载不修改它。品质分段及每日更新规则保留。剩余时间显示已改为除以实际速率，避免把陈酿单位误报成天数。

重型熔炉的八条默认配方迁入 `artisan/heavy_furnace.json`，不再使用 Java 静态配方表。`production/heavy_furnace.json` 的 `coal_per_batch` 默认 3，可配置 0–64。手动和自动化均使用同一配方及煤耗；只在计划接受后消耗资源。煤数量预检已修正重复计算主副手的问题。

artisan 新增可选 `maxOutputCount`，与 `outputCount` 组成均匀随机产量范围。不写时仍为固定产量。固定产物机器在真正启动批次时抽取，自动化模拟不抽取。重型熔炉默认 5–6 锭、火水晶 15–20 精炼石英的范围保持不变。特殊 seedmaker/smoked/copy_input 输出模式继续由各自解析器负责，不把这项范围套到特殊产物算法上。

## 重载与维护约定

- 按资源优先级读取覆盖；每个 profile 先与打包默认值合并，未写字段保留默认值。`cycles` 按名字合并，再按周期字段覆盖；`duration` 整体替换。`aging_rates` 按物品 ID 合并。
- 移除数据包并重载恢复默认，不能把上次覆盖残留成新的默认。
- 非法 JSON、未知字段、非正周期/倍数、未知产物、倒置产量范围等拒绝整批生产配置，保留上一份可用快照并记录日志；不会将某几台机器更新而另几台仍用旧配置。
- `/reload` 不扫描并改写已放置机器的 NBT，不重复投料、不重新抽产物。正在运行的生产仍保留原有截止时间、产物和已保存的速率。
- 配置只控制规则/数值；树是否完整、天空是否开放、职业效果、品质语义、交互和自动化协议仍由代码实现。

## 本轮审计中仍独立的系统

这次没有宣称把全模组所有数字都移出 Java。后续应分别处理：

| 系统 | 仍需迁出的平衡规则 | 合适的现有入口 |
| --- | --- | --- |
| 蟹笼 | 每日触发、基础垃圾概率、鱼饵双倍/减垃圾修正 | 现有 fishing 数据与职业/鱼饵规则 |
| 每日生产雕像、洞穴蘑菇盆 | 每日触发、固定/随机产出池 | 每日生产定义与 loot table；不要伪装成分钟配方 |
| 蜂房 | 花朵匹配表、搜索半径、风味蜂蜜价值 | 花朵/蜂蜜数据；保留采收时查询 |
| 普通炉和熏鱼机 | 额外燃料种类与用量 | artisan 额外输入定义；重型炉本轮已先接煤耗 |
| 织布机、孵化器等 | 品质/职业特例中的概率与倍率 | 既有职业或 artisan 规则，而非另增总配置开关 |
| 陈酿桶 | 品质阶段阈值 | 陈酿阶段定义，并给在途任务保存阈值快照 |
| 动物、鱼塘、作物与树木 | 各自生长/生产及地点条件 | 现有 animal / fishpond / crop / tree 数据体系 |

新增生产设施应首先选用现有配方或周期数据入口，数值默认值放 JSON；不要再新增一份 Java 私有配方/时长表。性能检查间隔、存档键、协议常量、日历单位无需一并变成玩法配置。
