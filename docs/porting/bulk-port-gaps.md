# 1.20.1 Forge 整体迁移：行为差异记录

## 网络（networking shim，`src/port/java/com/stardew/craft/port/internal/network`）

- 所有 NeoForge payload 走一个 Forge `SimpleChannel`（`stardewcraft:payloads`）的信封消息；wire id 按 payload id 排序分配（与监听器顺序无关）。各 registrar 的 version / optional / 方向折叠成频道协议版本，任何不一致在 Forge 登录握手时整连接拒绝（NeoForge 是逐 payload 协商）；`registrar.optional()` 因 Forge 频道整体必需而不再允许对端缺失（模组本身也有注册表同步，等价）。
- 超限 payload 自动分片：客户端方向单片 ≤1,000,000 字节、以 `ClientboundBundlePacket` 原子发送，重组上限 64 MiB；服务端方向单片 ≤30,000 字节，重组上限 8 MiB。`DataRegistrySyncPayload`（最大 16 MiB）依赖此分片。
- 编码在发送调用时立即进行（NeoForge 在 netty 管线中、且内存连接根本不编码）：编码异常直接抛给调用方；单人/局域网主机也总是走完整序列化。
- 配置阶段（1.20.1 不存在）映射到 Forge 登录握手：`RegisterConfigurationTasksEvent` 在 Forge 收集登录消息时（netty 线程，而非服务器主线程）按连接触发，每个任务 = 一次请求/应答往返；服务器端配置 handler 不能 `reply`（抛 `UnsupportedOperationException`），多轮往返任务不支持；任务未 `finishCurrentTask` 则断开连接（NeoForge 会卡到超时）。收集时 `getListener()` 只能按本地注册表回答 `hasChannel`，`disconnect` 作为特殊登录消息在客户端应答后由服务器执行。客户端可回填任意 taskId 应答，任务身份未与登录序号绑定（只防不兼容客户端，不防恶意客户端）。登录消息不分片，单个须 <1 MB。
- `ClientboundCustomPayloadPacket`（1.21.1）在 1.20.1 只是视图：测试拦截 `send(Packet)` 时需用 `ClientboundCustomPayloadPacket.unwrap(packet)`（已改所有 gametest 调用点）；`ServerGamePacketListenerImpl` 构造不再接受 `CommonListenerCookie`。
- `ItemStack` 流编码（`PortCodecs.ITEM_STACK/OPTIONAL_ITEM_STACK`）为 VarInt 数量 + 物品 id + Forge share tag；仅本模组 payload 生效，原版槽位同步仍受 1.20.1 字节数量限制（>127 堆叠见物品组）。组件文本走 1.20.1 JSON 编码。

## 注册表 / 附件 / 能力 / 数据映射 / 区块票据（`src/port/java/com/stardew/craft/port/{PortBootstrap,PortAttachments,PortCapabilities,PortDataMaps,PortAuxLight,PortNetwork}`）

- `DeferredHolder` 实现 1.20.1 `Holder<R>`（`get()/value()` 协变返回 `T`），但 1.20.1 的 `Holder` 已继承 `Supplier<R>`，不能再实现 `Supplier<T>`：需要 `Supplier<子类型>` 的调用点改用 `X::get`。1.20.1 原版 API 收 `MobEffect` 而非 `Holder<MobEffect>`，`ModMobEffects.X` 调用点已改为 `.get()`。
- `PortBootstrap` 由第一次 `DeferredRegister.register(modBus)` 安装：`RegisterDataMapTypesEvent`、`RegisterCapabilitiesEvent`、`RegisterTicketControllersEvent` 在通用设置阶段（`FMLCommonSetupEvent`，最高优先级）投递到模组总线，晚于 NeoForge 的触发时机，但仍早于任何世界/方块实体/区块。
- 数据附件只支持 `LevelChunk`（随区块保存，`ForgeCaps/stardewcraft:attachments`）和 `Player`（`copyOnDeath` 经 `PlayerEvent.Clone`；非死亡克隆全部复制）；其它持有者调用会抛 `UnsupportedOperationException`。存档格式不同于 NeoForge 的 `neoforge:attachments`（1.21.1 存档本来就不能降级读取）。
- 方块能力：`PortCapabilities.getCapability(level, cap, pos, side)` 取代 `level.getCapability`；注册过的能力同时以 Forge 能力挂到方块实体上供漏斗/管道使用。没有方块实体的方块（仅 `registerBlock` 注册）在 Forge 侧对其它模组不可见，只有本模组的 `PortCapabilities` 查询能拿到。`invalidateCapabilities` 只使本模组交出的 `LazyOptional` 失效。
- 区块票据：Forge 按 modid 管理票据，同命名空间的多个 `TicketController`（`portal_placement`、`npc_navigation`）共享票据集合，存档加载时每个控制器的校验回调都会看到全部票据（两者都是全部移除，行为一致）。
- 数据映射：`data/<ns>/data_maps/<registry>/<id>.json` 路径和格式保持不变（`replace`、`values`、标签、单值 `replace`、`remove`、`neoforge:conditions`/`forge:conditions`，条件类型 `neoforge:*` 映射为 `forge:*`）。服务端重载后在 `TagsUpdatedEvent(SERVER_DATA_LOAD)` 解析；同步类型在 `OnDatapackSyncEvent` 经独立频道 `stardewcraft:port_internal` 以 JSON 发给远程客户端（集成服务器客户端直接共享数据）。未实现 `DataMapsUpdatedEvent`（模组未使用）。读取改为 `PortDataMaps.getData(holder, type)`。
- 辅助光照（`getAuxLightManager`）：区块能力保存，区块发送给玩家后（`ChunkWatchEvent.Watch`）通过 `stardewcraft:port_internal` 补发；客户端收到区块包时先清空。Forge 没有 `hasDynamicLightEmission`，`TemplateBlock#getLightEmission` 对 `ChunkAccess#findBlocks` 的 `BlockPos.ZERO` 预筛探测返回 15 以达到同样效果。
- `FluidType.Properties#addDripstoneDripping` 在 Forge 1.20.1 不存在，1.20.1 滴水石把炼药锅灌注写死为水/岩浆：鱼塘水上方的滴水石不再灌满炼药锅（滴落粒子因 `minecraft:water` 流体标签仍为水滴）。
- `ModConfigSpec.BooleanValue#getAsBoolean` → `ForgeConfigSpec.BooleanValue#get`（调用点已改）；配置注册改为 `ModLoadingContext.get().registerConfig`，`IConfigScreenFactory.register(...)` 注册到 Forge `ConfigScreenHandler`。

## 物品数据组件 / ItemStack NBT（`src/port/java/com/stardew/craft/port/{PortItemData,PortItemStacks,PortItemNbt,PortAttributeModifiers}`，`port/net/minecraft/core/component/*`，`port/net/minecraft/world/item/{component,enchantment,alchemy}/*`）

- 组件直接映射到 1.20.1 原版物品 NBT（与原版/其它模组互通）：`custom_data`=根标签去掉保留键（`PortItemNbt.RESERVED_ROOT_KEYS`：Damage、RepairCost、Unbreakable、Enchantments、StoredEnchantments、display、HideFlags、CanDestroy、CanPlaceOn、AttributeModifiers、CustomModelData、BlockStateTag、BlockEntityTag、EntityTag、Trim、Potion、CustomPotionColor、CustomPotionEffects、Fireworks）；`custom_model_data`=`CustomModelData`（物品模型 `custom_model_data` 谓词照常生效）；`block_state`=`BlockStateTag`；`custom_name`=`display.Name`；`lore`=`display.Lore`；`enchantments`/`stored_enchantments`=`Enchantments`/`StoredEnchantments`（+HideFlags ENCHANTMENTS/ADDITIONAL 位）；`block_entity_data`=`BlockEntityTag` 去掉 `Items`；`container`=`BlockEntityTag.Items`（ContainerHelper 布局）；`unbreakable`=`Unbreakable`+HideFlags；`dyed_color`=`display.color`+HideFlags；`trim`=`Trim`（按当前逻辑端的 RegistryAccess 编解码）；`potion_contents`=`Potion`/`CustomPotionColor`/`CustomPotionEffects`；`fireworks`=`Fireworks{Flight,Explosions}`；`attribute_modifiers`=`AttributeModifiers`（槽组拆成逐槽条目，`ANY` 不写 Slot）。
- 组件读取返回快照：每次 `PortItemData.get` 都是新对象，不能再用 `==` 判断“组件未被重写”（`BlueprintPreviewSyncGameTests` 改为比较根标签值的引用）。写入会把空子标签/空根标签规整为不存在，保证 `isSameItemSameTags` 与新堆叠一致。对共享的 `ItemStack.EMPTY` 写入被忽略。
- 无法区分“显式设为空”与“不存在”：`set(CUSTOM_DATA, CustomData.EMPTY)` 后 `has` 为 false；`enchantments`/`lore` 与 1.21 一样对所有非空物品默认返回 `EMPTY`（`stored_enchantments` 仅附魔书）。`custom_data` 里若出现保留键名会直接写到根标签上成为原版数据（模组未这样用）。
- `item_name` 没有独立存储位：写成不斜体的 `display.Name`，与 `custom_name` 共用；读取在无名字时回退到物品名。
- `food` 只读（1.20.1 食物属性属于 Item），`set/remove` 抛 `UnsupportedOperationException`。
- 1.20.1 没有物品默认组件（`Item.Properties#component`）：斧/镐的隐藏 `unbreakable` 改为覆写 `isDamageable(stack)=false`（无耐久、无耐久条、无提示行）；赌场烟花的默认 `fireworks` 在 `initCapabilities`（Forge 在每个 ItemStack 构造时调用）写入堆叠 NBT；武器默认 `attribute_modifiers` 改为覆写 `getDefaultAttributeModifiers(EquipmentSlot)`（`ItemAttributeModifiers#portModifiers`）。
- 1.21 属性修饰符用 ResourceLocation 作 id；`PortAttributeModifiers.create(id, amount, op)` 由 id 派生确定性 UUID（名称为 id 字符串）。`Attributes.ENTITY_INTERACTION_RANGE` 在物品修饰符处改用 Forge `ForgeMod.ENTITY_REACH`。`EquipmentSlotGroup.BODY` 在 1.20.1 不匹配任何槽。`PortItemStacks.forEachModifier` 传入 `Attribute`（不是 `Holder<Attribute>`），与 1.20.1 的 `Attributes.X` 类型一致。
- 附魔：`ItemEnchantments` 的 holder 规范化为内置注册表引用；1.20.1 未注册的附魔 id（模组 1.21 数据驱动附魔若未在代码中注册）用共享的独立 `Holder.Reference`（仅 key，`value()` 不可用）保存，往返不丢 id、按 key 查等级仍有效，但原版不会生效也不显示提示行。`PortItemStacks.enchant` 采用 1.21 的 upgrade 语义（取较大等级，不重复追加）。`registryOrThrow(ENCHANTMENT).getHolderOrThrow(StardewEnchantments.X)` 在附魔未注册时运行期会抛出——需要附魔注册的移植来解决。
- 堆叠数量 >127（模组为 999）：1.20.1 的 NBT `Count` 与网络包数量都是 byte。`ItemStackLargeCountMixin` 在数量 >127 时把 `Count` 写成 int 并在读取时还原（≤127 仍写 byte，保持原版布局）；`FriendlyByteBufLargeItemCountMixin` 在数量 >127 时写标记字节 -128 + VarInt（≤127 仍为原版编码）。原版客户端/没有本模组的一端无法解析这类大堆叠（双端本就必须装模组）。
- 移除的 1.21.1 mixin：`DataComponentsMixin`（放宽 `max_stack_size` 组件 codec 上限；1.20.1 `stacksTo` 无上限）、`ItemStackCodecCountRangeMixin`（放宽 `ItemStack.CODEC` count 上限；1.20.1 CODEC 为无界 int），两者已从 `stardewcraft.mixins.json` 删除并由上一条的两个 mixin 取代。`ItemStackMixin`、`ItemStackStreamCodecRangeMixin`、`ItemStackValidatedStreamCodecMixin` 在 1.21.1 已未注册（死代码），目标方法在 1.20.1 不存在，已删除。
- `DataComponentPatch` 未实现垫片（唯一引用在已删除的 `ItemStackMixin`）；JEI 签名中的 `getComponents()/getComponentsPatch()` 改为 `getTag()`。
- `ItemStack.parse/parseOptional/save(provider)/saveOptional` → `PortItemStacks`（保留 provider 参数，1.20.1 NBT 格式 `{id, Count, tag, ForgeCaps}`）；1.21.1 存档中的物品 NBT（小写 `count`、`components`）不做转换。`BlockEntity#saveToItem(stack, provider)` → `saveToItem(stack)`。

## 事件与模组生命周期（`src/port/java/com/stardew/craft/port/event/*`，`port/net/neoforged/{fml/common,neoforge/{client/event,client/gui,client/extensions/common,event,common/damagesource}}`，`mixin/Port*`）

- `@EventBusSubscriber` 改为端口注解 `com.stardew.craft.port.net.neoforged.fml.common.EventBusSubscriber`（改写脚本已登记）。与 NeoForge 21.1 一样忽略 `bus`，由 `PortEventSubscribers` 在 `StardewCraft` 构造末尾按事件类型逐方法注册（`IModBusEvent` → 模组总线，其余 → `MinecraftForge.EVENT_BUS`），支持非 public 方法、同类混合两条总线。Forge 自带的 `Mod.EventBusSubscriber` 不再使用；手动 `EVENT_BUS.register(X.class)` 仍走 Forge 规则（只认 public 方法，现有调用点均为 public）。
- `StardewCraftClient` 不再是 `@Mod`（Forge 每个 modid 只能有一个），由 `StardewCraft` 通过 `DistExecutor` 在客户端构造。
- `EntityTickEvent` 由 mixin 在 `ServerLevel/ClientLevel#tickNonPassenger/tickPassenger` 包住 `tick()/rideTick()` 触发（同 NeoForge 位置）。其余 tick 事件由 Forge `TickEvent`（START=Pre，END=Post）桥接。
- 伤害序列（`LivingIncomingDamageEvent`/`DamageContainer`/`LivingDamageEvent.Pre/Post`）由 `PortLivingEntityDamageMixin`/`PortPlayerDamageMixin` 实现；Forge 自身的 `LivingAttackEvent/LivingHurtEvent/LivingDamageEvent` 仍照常触发（Incoming 在 LivingAttack 之后、Pre 在 LivingHurt 与护甲/魔法减伤之后、Post 在扣血之后）。未记录 `INVULNERABILITY` 减伤和盾牌格挡量（`getBlockedDamage/getShieldDamage` 恒为 0，模组未读取）；`addReductionModifier` 的修改值只影响记录的减伤量与后续伤害，不回灌原版护甲耐久计算。Forge 的 `LivingHurtEvent` 使伤害 ≤0 提前返回时，补发 Pre(0)，若 Pre 设为正值则按原版吸收/扣血逻辑补扣，再发 Post。`LivingDamageEvent` 加入 `shim-classes.txt`（Forge 同名类形状不同）。
- `BlockDropsEvent`：所有 `Block.dropResources` 重载经 mixin 捕获掉落实体后触发；经验初值为玩家破坏时 Forge `BreakEvent` 的经验（Forge 随后的 `popExperience` 被跳过），非玩家破坏为 0（与 Forge 1.20.1 一致，NeoForge 会按 `getExpDrop` 给经验）。
- `ItemEntityPickupEvent.Pre` 桥接 `EntityItemPickupEvent`：只映射 `TriState.FALSE`（取消）；`TRUE` 不映射，因为 Forge 的 ALLOW 会跳过入背包直接删物品（模组未使用 TRUE）；Forge 在 `pickupDelay>0` 时不触发事件。`Post` 桥接 `PlayerEvent.ItemPickupEvent`，在 `Player#take` 之前触发（NeoForge 之后）。
- `SweepAttackEvent` 在 `Player#attack` 的 `canPerformAction(SWORD_SWEEP)` 处触发：原版其它横扫前置条件不满足时 Forge 不会走到这里，事件不触发也无法强制横扫。
- `CanPlayerSleepEvent`：先按 Forge 1.20.1 规则（含 `SleepingTimeCheckEvent`）算出原版问题，事件结果不变时走 Forge 原流程（含 `PlayerSleepInBedEvent`），改成其它问题则直接返回，改成 null 时按 NeoForge 方式强制入睡。`CanContinueSleepingEvent` 桥接 `SleepingTimeCheckEvent`（仅已在睡觉的服务端玩家）与 `SleepingLocationCheckEvent`（服务端），无睡眠位置时 Forge 不触发。
- `PlayerEnchantItemEvent` 在 `EnchantedItemTrigger#trigger` 处触发（附魔台 lambda 内，已扣青金石之后）；附魔列表从物品上重建（含物品原有附魔，附魔台物品本无附魔）。
- `RegisterBrewingRecipesEvent` 在通用设置阶段（主线程）投递一次到游戏总线，写入 Forge 全局 `BrewingRecipeRegistry`；`getBuilder()` 返回端口 Builder（只有 `addRecipe`）。
- `RegisterClientExtensionsEvent`/`RegisterMenuScreensEvent` 在 `FMLClientSetupEvent` 的 `enqueueWork` 中投递到模组总线；扩展通过访问器 mixin 写入 Forge 的 `Item/Block/FluidType.renderProperties`、`MobEffect.effectRenderer`。
- `RenderGuiLayerEvent` 桥接 `RenderGuiOverlayEvent`，`VanillaGuiLayers` 常量映射到对应的 Forge `VanillaGuiOverlay` id；没有对应项的 NeoForge 层（camera overlays、spectator tooltip、experience level、demo、saving indicator）未提供，`getPartialTick()` 未提供（模组未用）。`RenderFrameEvent` 桥接 `RenderTickEvent`，`DeltaTracker` 两种 partial tick 都是暂停感知的 `renderTickTime`（1.20.1 无 tick 冻结）。
- `ChunkWatchEvent.Sent` → Forge `ChunkWatchEvent.Watch`（同样在区块包发送后触发）。`MobEffectEvent.Applicable#getEffectSource()` → `PortEventHooks.effectSource()`（mixin 在 `addEffect/forceAddEffect` 的 `canBeAffected` 检查期间提供来源）。`CriticalHitEvent` 的 NeoForge 形状改为 Forge 的 result/`damageModifier`，Forge 暴击总是禁用横扫。1.20.1 没有水平滚轮，`getScrollDeltaX` 视为 0。
- `ModelEvent.RegisterAdditional` 注册的 `ModelResourceLocation(id, "standalone")` 由 `PortModelBakeryStandaloneMixin` 按普通模型文件加载并保持 standalone 键（Forge 1.20.1 原本会当作方块状态变体并回落到缺失模型）；`ModifyBakingResult#getModels()` 键类型为 `ResourceLocation`。`RegisterGeometryLoaders` 只收路径，命名空间取当前模组。

## 原版 1.21 专有 API / 方块交互拆分（`src/port/java/com/stardew/craft/port/{PortBlockInteraction,PortBlockProperties,PortEntities,PortLevels,PortGameTests,PortParticles}`，`port/net/minecraft/{world/ItemInteractionResult,core/particles/ColorParticleOption,client/DeltaTracker,client/resources/PlayerSkin}`；脚本 `scripts/port/adapt_block_use.py`、`scripts/port/adapt_overrides_1201.py`）

- 方块交互：覆写 `useItemOn`/`useWithoutItem` 的方块实现 `PortBlockInteraction`（声明改为 public），最上层的这类模组类插入 `use` 桥接，按 1.21.1 `ServerPlayerGameMode#useItemOn`/`MultiPlayerGameMode#performUseItemOn` 的方块阶段重放：先 `useItemOn(手中物品)`，消耗动作则返回其 `result()`；结果为 `PASS_TO_DEFAULT_BLOCK_INTERACTION` 且为主手时调用 `useWithoutItem`，消耗动作才返回；否则返回 `PASS`，由 1.20.1 调用方继续 `Item#useOn`。潜行跳过与 Forge `RightClickBlock` 的 useBlock 结果仍由 1.20.1 调用方在 `use` 外判断。差异：成就触发器统一为 `ITEM_USED_ON_BLOCK`（1.21 对 useWithoutItem 触发 `DEFAULT_BLOCK_USE`，1.20.1 无此触发器）；NeoForge 的 `UseItemOnBlockEvent`（BLOCK 阶段）不在桥接中触发。`FriendshipDoorBlock` 的 `super.useWithoutItem` 改为 `DoorBlock#use(MAIN_HAND)`。gametest 中的 `BlockState#useItemOn/useWithoutItem` 改为 `PortBlockInteraction.stateUseItemOn/stateUseWithoutItem`（原版方块回落到 1.20.1 `use`）。
- `Block#codec()` 覆写和只被它使用的 `CODEC` 字段被删除（1.20.1 没有方块类型注册表，无运行期影响）。`playerWillDestroy` 改为 void（模组调用点都不使用返回值）。`BlockBehaviour` 中 1.20.5 改为 protected 的方法在 1.20.1 为 public，覆写已放宽为 public。
