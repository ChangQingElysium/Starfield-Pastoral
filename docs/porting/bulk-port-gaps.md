## 网络（networking shim，`src/port/java/com/stardew/craft/port/internal/network`）

- 所有 NeoForge payload 走一个 Forge `SimpleChannel`（`stardewcraft:payloads`）的信封消息；wire id 按 payload id 排序分配（与监听器顺序无关）。各 registrar 的 version / optional / 方向折叠成频道协议版本，任何不一致在 Forge 登录握手时整连接拒绝（NeoForge 是逐 payload 协商）；`registrar.optional()` 因 Forge 频道整体必需而不再允许对端缺失（模组本身也有注册表同步，等价）。
- 超限 payload 自动分片：客户端方向单片 ≤1,000,000 字节、以 `ClientboundBundlePacket` 原子发送，重组上限 64 MiB；服务端方向单片 ≤30,000 字节，重组上限 8 MiB。`DataRegistrySyncPayload`（最大 16 MiB）依赖此分片。
- 编码在发送调用时立即进行（NeoForge 在 netty 管线中、且内存连接根本不编码）：编码异常直接抛给调用方；单人/局域网主机也总是走完整序列化。
- 配置阶段（1.20.1 不存在）映射到 Forge 登录握手：实际生产调用只有 `PetCatalogHandshake` 和 `CapabilityNegotiationTask`，均为一次 server offer / client reply / server finish。`RegisterConfigurationTasksEvent` 和 `task.run` 在服务器主线程触发；Forge 的入口链是 `ServerHandshakePacketListenerImpl.handleIntention` → `ServerLifecycleHooks.handleServerLogin`（`allowLogins` 已开启）→ `NetworkHooks.registerServerLoginChannel` → `HandshakeHandler` 构造/收集。Netty 入口排队后等待已运行的 server workqueue，服务器线程入口直接执行，不 join 自己；这两种现有任务仅读取/冻结目录和生成广告，不等待 Netty。服务器处理 reply 前通过 `PortHandshakeHandlerAccessor` 读取本连接发出的消息及仍 pending 的登录序号，严格核对序号、频道、消息类型、taskId；错任务、未发送序号、重放、假/非登录连接不进入 payload handler；拒绝提示复用原版已本地化的 unexpected_query_response，不新增硬编码玩家文案。`finishCurrentTask` 只能结束该请求的任务，服务器拒绝原因取自自身请求而非客户端回填。服务器端配置 `reply`/多轮往返仍不支持，但本模组没有调用，属于未使用 API 限制，不是遗漏游戏功能；登录消息不分片（现有两个请求远小于 1 MB）。任务未 finish 则断开而不是等超时。收集时 `hasChannel` 基于本地注册表，连接双方完整 payload 协议由 Forge 频道握手保证。定向测试 `PortLoginTasksGameTests` 覆盖正确/错位/重放请求、完成任务身份、主线程内外调度和正常/假/已关闭连接边界（本轮 4 项定向用例已实际通过）。
- `ClientboundCustomPayloadPacket`（1.21.1）在 1.20.1 只是视图：测试拦截 `send(Packet)` 时需用 `ClientboundCustomPayloadPacket.unwrap(packet)`（已改所有 gametest 调用点）；`ServerGamePacketListenerImpl` 构造不再接受 `CommonListenerCookie`。
- `ItemStack` 流编码（`PortCodecs.ITEM_STACK/OPTIONAL_ITEM_STACK`）为 VarInt 数量 + 物品 id + Forge share tag；仅本模组 payload 生效，原版槽位同步仍受 1.20.1 字节数量限制（>127 堆叠见物品组）。组件文本走 1.20.1 JSON 编码。

## 注册表 / 附件 / 能力 / 数据映射 / 区块票据（`src/port/java/com/stardew/craft/port/{PortBootstrap,PortAttachments,PortCapabilities,PortDataMaps,PortAuxLight,PortNetwork}`）

- `DeferredHolder` 实现 1.20.1 `Holder<R>`（`get()/value()` 协变返回 `T`），但 1.20.1 的 `Holder` 已继承 `Supplier<R>`，不能再实现 `Supplier<T>`：需要 `Supplier<子类型>` 的调用点改用 `X::get`。1.20.1 原版 API 收 `MobEffect` 而非 `Holder<MobEffect>`，`ModMobEffects.X` 调用点已改为 `.get()`。
- `PortBootstrap` 由第一次 `DeferredRegister.register(modBus)` 安装：`RegisterDataMapTypesEvent`、`RegisterCapabilitiesEvent`、`RegisterTicketControllersEvent` 在通用设置阶段（`FMLCommonSetupEvent`，最高优先级）投递到模组总线，晚于 NeoForge 的触发时机，但仍早于任何世界/方块实体/区块。
- 数据附件只支持 `LevelChunk`（随区块保存，`ForgeCaps/stardewcraft:attachments`）和 `Player`（`copyOnDeath` 经 `PlayerEvent.Clone`；非死亡克隆全部复制）；其它持有者调用会抛 `UnsupportedOperationException`。存档格式不同于 NeoForge 的 `neoforge:attachments`（1.21.1 存档本来就不能降级读取）。
- 方块能力：`PortCapabilities.getCapability(level, cap, pos, side)` 取代 `level.getCapability`；注册过的能力同时以 Forge 能力挂到方块实体上供漏斗/管道使用。NeoForge 可直接在无 BE 扩展格查询 block capability；Forge 的真实漏斗和普遍第三方管道却先读 `level.getBlockEntity(pos)`。为恢复这条外部路径，`PortMachineExtensions` 仅为 `UtilityAutomationCapabilities` 原有 25 个 `ItemHandler.BLOCK` 注册机器的空扩展工厂返回 Forge 专用代理 BE；注册清单与 BE 类型 valid blocks 使用同一个方法。代理无库存、无生产身份、无 tick、无 renderer，直接返回主格 Forge handler，并随主格 optional 或自身拆除/卸载失效；主格缺失时为空，重新查询可重新绑定。装饰格、农场电脑、冰箱等未注册机器块不会增加代理。此处仅 Forge 平台结构由“扩展格无 BE”变为“扩展格无库存代理”，唯一生产实体、配方、产出及拆除掉落保持不变；三套 footprint 测试如实检查代理而非重复生产实体。`PortAutomationExtensionGameTests` 覆盖 25 机器×四朝向、六面/无侧 Forge 查询、生命周期以及真实小桶主格/水平扩展格漏斗输入输出和防重复（本轮 3 项定向用例已实际通过）。`rewrite_1201.py` 保留此机械转换用于后续同步。
- 区块票据：Forge 按 modid 管理票据，同命名空间的多个 `TicketController`（`portal_placement`、`npc_navigation`）共享票据集合，存档加载时每个控制器的校验回调都会看到全部票据（两者都是全部移除，行为一致）。
- 数据映射：`data/<ns>/data_maps/<registry>/<id>.json` 路径和格式保持不变（`replace`、`values`、标签、单值 `replace`、`remove`、`neoforge:conditions`/`forge:conditions`，条件类型 `neoforge:*` 映射为 `forge:*`）。服务端重载后在 `TagsUpdatedEvent(SERVER_DATA_LOAD)` 解析；同步类型在 `OnDatapackSyncEvent` 经独立频道 `stardewcraft:port_internal` 以 JSON 发给远程客户端（集成服务器客户端直接共享数据）。未实现 `DataMapsUpdatedEvent`（模组未使用）。读取改为 `PortDataMaps.getData(holder, type)`。
- 辅助光照（`getAuxLightManager`）：区块能力保存，区块发送给玩家后（`ChunkWatchEvent.Watch`）通过 `stardewcraft:port_internal` 补发；客户端收到区块包时先清空。Forge 没有 `hasDynamicLightEmission`，`TemplateBlock#getLightEmission` 对 `ChunkAccess#findBlocks` 的 `BlockPos.ZERO` 预筛探测返回 15 以达到同样效果。
- `FluidType.Properties#addDripstoneDripping` 在 Forge 1.20.1 不存在，1.20.1 滴水石把炼药锅灌注写死为水/岩浆：鱼塘水上方的滴水石不再灌满炼药锅（滴落粒子因 `minecraft:water` 流体标签仍为水滴）。
- `ModConfigSpec.BooleanValue#getAsBoolean` → `ForgeConfigSpec.BooleanValue#get`（调用点已改）；配置注册改为 `ModLoadingContext.get().registerConfig`，`IConfigScreenFactory.register(...)` 注册到 Forge `ConfigScreenHandler`。

## 运行期等价修复：方块实体数据包 / 无通道连接 / 旋转 / 辅助光 / 空栈组件（`port/PortBlockEntityPackets`、`port/PortItemData`，`mixin/Port{NetworkHooksChannel,BlockRotation,LevelChunkAuxLight}Mixin`）

- 方块实体数据包：1.20.1 `ClientboundBlockEntityDataPacket` 把空更新标签存成 `null`（线上也写 `null` NBT），1.21.1 恒为非空 `CompoundTag`（`TRUSTED_COMPOUND_TAG`）。模组中把数据包当完整快照处理的 `onDataPacket`（`PlacedFishBlockEntity`、`FishMarketCrateBlockEntity`、`AquariumBlockEntity`、`TemplateBlockEntity`）改用 `PortBlockEntityPackets.tag(packet)`，`null` 视为空标签，空包照 1.21.1 清空旧鱼/材质。其它方块实体走 Forge 默认处理（跳过 `null`），与 NeoForge 默认（跳过空标签）等价，未改动。
- 无 Netty 通道的连接：Forge 1.20.1 的 `TierSortingRegistry` 在 `PlayerLoggedInEvent` 中调用 `SimpleChannel#isRemotePresent`，经 `NetworkHooks.getConnectionData/getChannelList` 直接读 `connection.channel().attr(..)`，对未连接的 `new Connection(flow)`（GameTest 登录探针，以及 Forge 自己的 `FakePlayer` 网络处理器）抛 NPE，后续监听器（模组登录同步）全部不执行。NeoForge 1.21.1 没有该登录监听器。`PortNetworkHooksChannelMixin` 让这三个 `NetworkHooks` 读取函数在 `channel()==null` 时返回 `null`（调用方已把 `null` 当作“远端无此通道”）。这是 Forge 全局行为变化：只把原本的崩溃改为“无握手数据”，有通道的真实连接不受影响。
- 旋转/镜像：1.21.1 原版 `DecoratedPotBlock`、`BellBlock` 覆写了 `rotate`/`mirror`（水平朝向随旋转；镜像 = 按 `mirror.getRotation(facing)` 旋转），1.20.1 两者都没有，结构/预制件旋转时朝向不变。逐类对比 1.20.1 与 1.21.1 全部原版方块的 `rotate`/`mirror` 实现，只有这两类不同（铁轨类 1.21 的写法变化结果相同；`RedstoneWallTorchBlock` 1.20.1 委托 `WALL_TORCH`，结果相同）。`PortBlockRotationMixin` 在 `BlockBehaviour#rotate/mirror` 头部只对这两类返回 1.21.1 结果。影响全部使用这两种方块的结构放置（含原版结构），与 1.21.1 原版一致。
- 辅助光：NeoForge 1.21.1 在 `LevelChunk#removeBlockEntity` 和 `setBlockEntity`（被不同实例替换时）中，紧跟在旧方块实体 `setRemoved()` 之后调用 `auxLightManager.removeLightAt(pos)`；1.20.1 移植的 `PortAuxLight` 原本没有这一步，破坏模板方块后会留下幽灵光。`PortLevelChunkAuxLightMixin` 在同样的位置补上（客户端与服务端都生效）。
- 空栈的组件读取：1.21.1 `ItemStack#getComponents()` 对空栈（空气或数量 <= 0，例如 `shrink` 后）返回 `DataComponentMap.EMPTY`，因此 `get/getOrDefault/has` 读不到任何组件，但数据仍保存在栈上，数量恢复后重新可见；`set/remove` 返回原始旧值。`PortItemData` 的读取原来直接读 NBT，数量为 0 的栈仍能读出数据（例如已消耗的建筑搬迁文书仍被 `isMove` 识别）。现已按 1.21.1 处理。仍有的差异：直接调用 1.20.1 原版 API（`getTag`、`getHoverName` 等）时，数量为 0 的栈仍能读到其 NBT。

## 运行期等价修复：植物土壤支持 / 耕地 / 楼梯（`port/PortPlantSupport`、`port/PortStairBlock`，`mixin/Port*PlantSupportMixin`、`PortRabbitRaidFarmlandMixin`）

- 原因：NeoForge 1.21.1 的植物先问土壤 `canSustainPlant(state, level, pos, facing, BlockState plant) -> TriState`，非 DEFAULT 直接决定存活（不再查光照/水/标签），DEFAULT 回到原版规则；原版规则接受任意 `FarmBlock` 子类（`instanceof FarmBlock`），`isFertile` 对任意湿润 FarmBlock 为真。Forge 1.20.1 是布尔钩子 `canSustainPlant(..., IPlantable)`，默认实现在 `mayPlaceOn` 之外再叠加 Forge 植物类型规则（如所有 PLAINS 植物可种在任意 `#dirt`），只有少数植物会问它，原版规则与 `isFertile` 只认 `Blocks.FARMLAND`。结果：小麦等原版作物/茎不能种在模组耕地（`FARMLAND`、`INFERTILE_FARMLAND`、沙质耕地、花园盆）上，湿润模组耕地不给生长加成，花园种植箱上的作物在暗处掉落、竹子/垂滴叶/紫颂等无法种植，枯萎作物（`DeadCropBlock`，只认 FarmBlock）在 1.20.1 还能留在泥土上。
- 修复：`GardenPlanterBlock` 实现 `PortPlantSupport.Soil`（1.21.1 原方法体）；mixin 按 1.21.1 复刻 `BushBlock`（`mayPlaceOn` 与 `canSurvive`）、`CropBlock`（`mayPlaceOn`、`canSurvive` 光照为 1.21.1 的 `rawBrightness >= 8`、无天空例外、`getGrowthSpeed`）、`StemBlock`/`AttachedStemBlock`（`mayPlaceOn`，结果实只放在 FarmBlock 或 `#dirt` 上）、`PitcherCropBlock`、`MushroomBlock`、`CactusBlock`、`SugarCaneBlock`、竹子两类、大/小垂滴叶、可可、红树胎生苗、紫颂花/紫颂植株（连接、存活、生长）、`FarmBlock`（新增 `isFertile` 覆写；干耕地只在 `#maintains_farmland` 下保留）、兔子偷胡萝卜（任意 FarmBlock）。这些是对原版类的全局修改，在整个世界与 1.21.1 原版一致。
- 兼容取舍：覆写了 Forge 布尔钩子的第三方土壤（`PortPlantSupport.legacyForgeSoil`，原版和本模组都没有这种方块）在 1.20.1 原本会问 Forge 钩子的位置（灌木、作物生长、蘑菇、仙人掌、甘蔗、茎结果、耕地保持）仍用其布尔结果；在 1.20.1 本来不问土壤的位置（竹子、垂滴叶、可可、紫颂、红树苗）不问第三方土壤。仅在与其它 Forge 模组共存时有意义，对本模组内容无影响。
- 紫颂：保留 Forge 1.20.1 的 `#forge:chorus_additionally_grows_on` 标签（原版为空，与 1.21.1 等价）。紫颂花 `randomTick` 中柱底土壤的坐标按 1.21.1 的循环重新计算（只有 `Soil` 方块才走此路径，`GardenPlanterBlock` 不读坐标）。
- 楼梯：1.20.1 `StairBlock` 把 animateTick/attack/destroy/onPlace/onRemove/stepOn/isRandomlyTicking/randomTick/tick/use/wasExploded 转发给基底方块，1.21.1 只保留爆炸抗性。草基底楼梯因此会随机刻并按草方块衰减/蔓延。模组楼梯（`ModBlocks.stairs/stairsFromAnyBlock`、`TerrainStairBlock`）改为继承 `PortStairBlock`，以上方法恢复为 1.21.1 默认实现。原版及其它模组的楼梯保持 1.20.1 行为（不影响本模组逻辑）。注：另一个代理同时在 `TerrainStairBlock` 中加入了同样的覆写，现在与 `PortStairBlock` 重复（结果相同），可以删除。
