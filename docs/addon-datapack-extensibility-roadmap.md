# StardewCraft 附属与数据包平台规划 v6

> 状态：实施总纲
>
> 基准日期：2026-07-27
>
> 适用范围：0.5.x 的兼容式演进与后续稳定版本
>
> 北极星：本体的每个主要游戏系统都为未知的未来附属提供稳定、可组合、可恢复的扩展路径
> 发布底线：能启动、能进档、能保存、能重载；没有扩展时原玩法不变

## 1. 我们要建设什么

StardewCraft 要提供一套通用玩法平台，而不是替某一个已存在的附属减少补丁。

扩展作者最终应能组合出以下完整玩法，而无需修改本体名单、固定坐标、菜单分支、网络分支或
存档实现：

- 多种农场与非农场地图布局，以及地点、区域、锚点、传送和安全返回；
- 具有生成、日程、对话、礼物、友情、商店、剧情和持久状态的 NPC；
- 可获得、可使用、可生产、可保存、可展示的物品、食物、作物、树木、动物、建筑和机器；
- 具有场地、参与者、阶段、玩法、货币、奖励和异常恢复的节日或世界活动；
- 可保存、可追踪、不可重复领奖的任务、收藏、成就和长期进度；
- 钓鱼、矿井、战斗、掉落和世界事件等高频或随机玩法；
- 本体菜单、配方查看器、信息提示和调试工具中的一致展示。

现有外部项目只能作为独立兼容样本，不能成为命名、数据结构或运行语义的来源。生产代码、
公共文档和通用示例不得出现具体附属身份或为其增加专用判断。

## 2. 明确不做什么

- 不一次重写全部系统，也不建立一个控制所有内容的“万能注册表”；
- 不为了形式统一改变原有价格、掉落、随机序列、日结顺序或实体生命周期；
- 不开放任意脚本、任意类名反射、跨命名空间裸 NBT、无界 tick 回调或全世界扫描；
- 不让客户端决定价格、库存、奖励、进度、传送位置或任何持久状态；
- 不先公开 Screen、Menu、实体实现类等内部细节，再补服务端契约；
- 不以公共类数量、代码行数、示例数量或某个附属少写了多少补丁衡量完成度；
- 不把编译成功、到达主菜单或单机 GameTest 当作真实联网通过；
- 不把只有一个消费者、没有迁移语义的内部抽象提前宣布为稳定 API。

## 3. 六条不可破坏契约

### 3.1 空扩展等价

所有扩展点为空时必须回到原路径：

- 分支顺序和随机调用次数不变；
- 不额外生成实体、物品或存档记录；
- 不把解析失败当作“允许”；
- 不要求客户端安装未使用的额外内容；
- 不改变已有数据包和 Java 入口的默认值。

每个新扩展点都要有空注册回归测试。

### 3.2 服务端权威

客户端只提交意图、稳定 ID、服务端签发的 revision/会话信息和幂等键。服务端重新解析并完成：

`Intent → Resolve → Validate → Prepare → Commit → Receipt`

购买、领奖、生产、迁移和世界修改不得拆成可被重复或越权调用的多次写入。

### 3.3 存档不丢未知数据

扩展暂时卸载或数据包暂时缺失时：

- 未知 owner 的状态原样往返保存；
- 只报告 orphan，不自动删除、替换或归零；
- 重新安装后按原稳定 ID 恢复；
- schema 迁移失败时保留原始数据；
- 清理或迁移必须先预览、备份，再由管理员确认。

这项承诺只覆盖 StardewCraft 平台管理的命名空间状态。附属直接注册到 Minecraft 原生注册表的
方块、物品或实体，在附属完全缺失时仍受 Minecraft 的缺失注册项行为约束；不得宣称平台能
无损保留这些原生对象。测试缺失附属的旧档必须使用副本，正式档必须先备份，并避免在缺失
附属时加载和保存含其原生对象的区块。

### 3.4 原子发布

内容 reload 固定为：

`解析候选 → 校验 → 解析引用 → 应用 patch → 构建索引 → 验证 → 一次发布`

任何步骤失败时保留上一个完整 revision。只有必须共同成立的数据共享事务；互相独立的目录
独立降级，不能因一份活动文件错误回滚所有玩法目录。

### 3.5 兼容式演进

对已经公开或可能被外部使用的入口，顺序固定为：

1. 记录 JVM 描述符、数据格式、网络 ID、存档 schema 和现有运行语义；
2. 新实现先放在兼容桥后；
3. 旧入口继续转发并保持默认值、异常和调用顺序；
4. 新入口先标实验；
5. 独立样本证明新旧路径一致；
6. 至少经过一个明确兼容周期后再讨论弃用；
7. 删除另开独立变更，不与功能扩展混在一起。

### 3.6 有界失败

每个扩展点必须声明最大条目数、字符串长度、嵌套深度、调用频率和线程。一个处理器异常只影响
它自己的结果；核心根据公开契约选择继续、拒绝、回退或补偿，并留下可读诊断。

## 4. 平台共同骨架

每个领域都沿用同一条能力链，但保持自己的强类型数据：

`Definition → Catalog → Reference → Runtime → State → Operation → Sync/View → Diagnostics`

### 4.1 Definition：定义

数据包表达可声明、可校验的事实：

- 完整命名空间 ID、格式版本和默认值；
- 标签、条件、引用与展示元数据；
- 明确的 `add`、`patch`、`replace`、`remove`；
- 有界列表和结构。

数据包不能直接执行 Java、访问裸 NBT 或修改世界。

### 4.2 Catalog：活动目录

领域目录发布不可变快照，至少包含：

- revision；
- 完整 ID 索引与稳定排序视图；
- 必要的派生索引；
- 来源、冲突、未解析引用和失败诊断；
- 客户端需要的有界展示 DTO。

目录失败不发布半成品，构建展示快照失败也不得清空上一个可用快照。

### 4.3 Reference：引用

跨系统传递强类型稳定 ID，不复制对象、私有字段或硬编码坐标。解析结果区分：

- 已解析；
- 可选缺失；
- 必需缺失；
- 类型错误；
- 循环引用；
- alias 迁移。

地点、区域、NPC、节日、任务、商店、机器、奖励和进度都使用同一种命名空间规则。

### 4.4 Runtime：有界行为

Java 附属只承担难以安全数据化的部分，例如 Provider、Resolver、Validator、Lifecycle
listener、Action handler 和 Reward grant。每个扩展点公开：

- 输入上下文和返回结果；
- `PASS`、接受、拒绝与异常语义；
- 排序、短路和组合规则；
- 调用线程与生命周期；
- 输出和耗时预算；
- reload 后旧实例如何退出。

### 4.5 State：状态

状态键由“作用域 + owner + schema + key”构成。作用域覆盖世界、农场、玩家、NPC、动物、
建筑、机器、地点实例、节日会话、团队任务和长期进度。

附属默认只能访问自己的 owner 空间。跨附属协作通过公共服务和明确授权完成。

### 4.6 Operation：权威事务

改变游戏状态的操作必须返回强类型结果。结果至少区分：

- 成功；
- 条件不满足；
- 资源不足；
- 内容缺失；
- 冲突或已处理；
- 暂时不可用；
- 提交前失败；
- 已回滚或需要恢复。

购买、奖励、领奖、生产、升级、迁移和世界修改使用幂等键或等价防重机制。

### 4.7 Sync/View：同步与展示

客户端只接收稳定 ID、server epoch、revision、文本 key、图标/物品引用、有界列表、原因码和
服务端确认的价格/库存/进度。规则是：

- 独立异步更新的快照中，旧 revision 不能覆盖同一 server epoch 的新快照；
- 断开服务器时清空会泄漏到下一服务器的缓存；
- 缺少翻译时显示可读 ID，不显示空白；
- 缺少图标、模型或肖像时使用通用占位，不隐藏玩法条目；
- 可选集成刷新失败不撤销已收到的权威快照；
- 展示失败永远不能反向改变服务端结果。

### 4.8 Diagnostics：诊断

管理员和作者应能查询：

- 定义来源、活动 revision、最终顺序和冲突；
- 未解析引用、alias 和降级原因；
- 处理器接受、拒绝、异常与耗时；
- orphan 状态、schema 和迁移预览；
- 权威操作阶段、收据、回滚与恢复记录。

查询默认只读。任何修复命令与查询命令分开。

## 5. 多附属组合规则

所有组合使用完整 ID 和显式 owner，不依赖加载顺序。默认排序键为：

1. 领域定义的阶段；
2. 显式优先级；
3. owner ID；
4. 注册 ID。

只允许以下公开组合语义：

- `PASS`：不参与；
- `ALLOW` / `DENY`：按领域规定的拒绝优先或首个决定规则；
- `ADD`：追加不互斥结果；
- `PATCH`：只修改公开字段并记录来源；
- `REPLACE`：显式替换，冲突必须可诊断；
- `REMOVE`：只移除公开可移除条目，不删除持久状态。

重复 ID、循环引用、多个 replace、必需依赖缺失和越界输出不能静默选择赢家。

## 6. 全游戏能力矩阵

“支持某个系统”不是只有一个注册方法，而是完成该行实际需要的整条能力链。

| 领域 | 数据定义 | Java 行为 | 状态/事务 | 同步与降级 |
|---|---|---|---|---|
| 世界与地图 | 地点、区域、槽位、锚点、布局、Portal | 选点、生成约束 | 安全落点、返回、迁移 | 缺失地点原因码 |
| 农场与建筑 | 布局、蓝图、升级、区域规则 | 施工校验、生命周期 | 所有权、原子施工、回滚 | 服务端预览与 revision |
| 物品与食物 | 语义、标签、来源、食物效果 | 动态效果条件 | 权威消耗和效果 | 任意已有物品、缺图仍可用 |
| 作物与树木 | 阶段、季节、产出、位置规则 | 特殊生长/收获 | 日结、卸载恢复 | 手工和自动化一致 |
| 动物与住所 | 类型、商店、产物、住所 | 行为、繁殖、特殊产出 | 记录/实体同步、防复制 | 缺实体时保留记录 |
| 机器与生产 | 输入、输出、周期、副产物 | 动态配方 | 原子输入输出、取消、重启 | 状态预览而非客户端写入 |
| 合成与烹饪 | 配方、解锁、效果、来源 | 动态解锁 | 权威消耗 | 菜单和集成同一目录 |
| NPC 与社交 | Profile、日程、对话、礼物、关系 | 实体解析、互动 | 友情、生成、卸载恢复 | 缺翻译/肖像使用占位 |
| 剧情与邮件 | 触发、条件、动作、邮件、奖励 | 自定义条件/动作 | 幂等完成、多人策略 | 只同步安全展示元数据 |
| 商店与经济 | 条目、货币、成本、库存、限购 | 动态成本/交付 | 防重购买、收据、补偿 | 客户端价格不授权 |
| 节日与活动 | 日期、场地、参与者、阶段、奖励 | 强类型玩法 | 会话、跨日、异常恢复 | epoch + revision |
| 任务与进度 | 目标、奖励、收藏、统计 | 目标/进度来源 | 防重复领奖、orphan 保留 | 有界进度 DTO |
| 钓鱼与鱼塘 | 鱼池、条件、宝箱、鱼塘规则 | 动态判定 | 随机流、鱼塘状态 | 展示与实际解析同源 |
| 矿井与战斗 | 主题、房间、怪物、掉落、效果 | 生成/战斗处理器 | 楼层状态、奖励 | 密度和效果有预算 |
| 世界事件 | 区域、持续时间、清理条件 | 有界事件计划 | 原子放置、回滚、重启清理 | 只同步结果和状态 |
| 展示与集成 | 文本、图标、模型、页面描述 | 受控页面提供器 | 不持有玩法事实 | 统一 DTO、资源降级 |

## 7. 已有改动的归类规则

### 7.1 保留并继续验证

- 有序注册、冻结、revision、来源和指标；
- 可选/必需网络能力协商；
- 强类型引用、alias 和引用诊断；
- 未知命名空间状态保留、导出和预览迁移；
- 对任意已有食物生效的数据化效果；
- 地点、区域、锚点、布局和蓝图的稳定身份；
- 单一一致性边界内的原子目录快照；
- 幂等购买/奖励、世界事件事务；
- API 基线、独立样本、GameTest 和兼容检查。

### 7.2 逐步收敛，不改变行为

- 重复实现排序、冻结和诊断的注册表；
- 同一一致性边界中分开发布的定义与派生索引；
- 各系统重复维护的地点、NPC 或内容身份；
- 分散的购买、退款、奖励和领奖结果；
- 本体菜单和可选集成维护的第二套内容事实。

收敛通过共享小协议和旧入口桥完成，不做全局重写。

### 7.3 保持实验或转内部

满足任一条件时不得稳定化：

- 只有一个独立消费者；
- 暴露实现细节而不是作者用例；
- reload、异常、存档、网络或多人语义不完整；
- 无法解释两个扩展同时参与的结果；
- 没有空扩展等价、独立样本或预算证据。

### 7.4 撤回

- 为具体地图、角色、活动或物品写的专用判断；
- 任意脚本、任意类反射、跨 owner 裸 NBT；
- 客户端直接写服务端状态；
- 无界回调、无界集合、全世界扫描；
- 静默覆盖重复 ID；
- 内容缺失时自动清除状态。

只有“未发布、无消费者、无存档影响”的候选可以直接删除；其他入口走兼容桥。

## 8. 实施方法：纵向能力包

后续不再按“再增加一批 API”施工。每个批次只关闭一个真实作者用例，并包含：

1. 一个数据定义；
2. 一个运行时入口；
3. 一个需要时的命名空间状态；
4. 一个服务端权威操作；
5. 一个客户端只读视图；
6. 一个诊断入口；
7. 一个独立样本；
8. 一组兼容和恢复门禁。

单批默认只碰一个主要领域。若需要同时改公共 API、网络协议、存档 schema 和原有玩法行为，
必须拆批；不能用“统一设计”作为扩大变更面的理由。

## 9. 分阶段路线

### 阶段 A：安全基线与平台内核

交付：

- 启动、新档、用户旧档副本、保存重载和专服 smoke；
- API 成熟度分类与二进制基线；
- 原子目录、强类型引用、alias、命名空间状态；
- 网络能力协商、同步上限、诊断和性能计数；
- 空扩展等价测试。

退出：上述门禁可重复运行，失败不会破坏用户存档。

### 阶段 B：空间闭环

交付：

- 地点、区域、槽位、锚点、布局、Portal；
- 多种农场和非农场布局；
- 建筑蓝图、升级、位置迁移；
- NPC、节日、钓鱼、采集、任务、音乐和传送共同消费；
- 一个与本体内容无关的地图样本。

退出：地点只定义一次，至少五类系统复用；不再新增固定坐标分支。

### 阶段 C：内容与生产闭环

交付顺序：

1. 物品语义、获得来源、任意食物效果；
2. 配方、解锁、商店和统一展示；
3. 作物和树木；
4. 动物和住所；
5. 机器完整生命周期；
6. 手工与自动化一致性。

退出：第三方已有食物无需替换 Item 类即可获得效果；取消、卸载和重启不复制或吞物。

### 阶段 D：角色与服务闭环

交付：

- Profile、实体解析、生成/移除；
- 基于阶段 B 地点与锚点的日程；
- 对话、礼物、友情和关系 patch；
- 商店绑定与通用 Action；
- 剧情、邮件、奖励和幂等完成；
- 多人友情/剧情策略；
- 一个贯穿全链的独立角色样本。

退出：新角色不需要本体名单、坐标表、菜单或网络分支；卸载后状态保留，重装后恢复。

### 阶段 E：活动、经济与长期进度闭环

交付：

- 节日场地、参与者、阶段和强类型活动；
- 会话状态、跨日与异常恢复；
- 通用货币、复合成本、库存、限购；
- 任务、特殊订单、社区和收藏进度；
- 奖励、收据、幂等与补偿；
- 一个独立活动和长期进度样本。

退出：重复请求不重复扣费/发奖；暂时卸载不清除历史状态。

### 阶段 F：高频、随机与世界事件闭环

交付：

- 钓鱼、宝箱、鱼塘；
- 矿井主题、房间、结构和楼层状态；
- 怪物、环境、密度、战斗和奖励；
- 世界事件原子生成、清理和恢复；
- 独立随机流、空间索引和性能预算；
- 高频压力样本。

退出：空扩展随机黄金序列不变；无无界扫描；世界修改失败不留半成品。

### 阶段 G：展示、文档与稳定发布

交付：

- 菜单、图鉴、商店、配方和信息提示使用统一 DTO；
- 缺失翻译、图标、模型和肖像的降级；
- 独立异步快照在同一 server epoch 下拒绝重复或旧 revision；
- 断线清缓存、重连和跨服务器隔离；
- 作者模板、格式、迁移和诊断手册；
- 稳定 API/数据基线与完整发布门禁。

退出：展示错误不影响服务端；任何提升到预览的 API 已有至少两类独立消费者；真实联网和重连
通过。证据不足的入口继续保持实验，不以阶段完成为由批量提升。

## 10. 验证门禁

### 10.1 每批必跑

- 编译与单元测试；
- 领域 focused tests；
- 空扩展等价；
- 公共 API 与旧入口兼容；
- 示例 Java 附属独立构建；
- 示例数据包解析和跨文件引用；
- 对应 GameTest；
- `git diff --check`；
- 生产代码、文档和通用示例中的具体附属身份扫描。

### 10.2 按风险追加

| 改动 | 必须追加 |
|---|---|
| reload/目录 | 原子切换、失败保留旧 revision、独立目录降级 |
| 存档/状态 | 新档、旧档副本、重载、卸载、重装 |
| 网络/购买 | 可选降级、必需拒绝、防重、断线、重连 |
| 机器/世界修改 | 取消、卸载、重启、提交失败、补偿 |
| 高频/随机 | 黄金序列、组合顺序、压力预算、扫描审计 |
| 客户端展示 | 缺资源、旧 revision、跨服务器缓存、服务端不受影响 |

真实运行时通过标准是玩家实际进入世界并稳定 tick，或专服完成保存和正常退出。编译成功、
进入主菜单和客户端进程开始启动都不能替代。

## 13. 本轮收口结果

本轮停止横向增加 API，阶段 G 按以下顺序关闭：

1. **自动化客户端降级门禁（已完成）**
   展示快照构建失败保留旧值；缺失翻译显示可读 ID；缺失肖像/图标使用占位但不隐藏条目；
   同一 server epoch 的旧 revision 不覆盖新值；断线清理跨服务器缓存。
2. **真实多人联网门禁（已完成）**
   客户端连接旧档副本专服；首次与重连均重新协商能力、加载玩家数据并稳定运行至少 10 秒；
   断线保存玩家状态，专服最终完整保存全部维度。验证器要求 13 个有序标记，不接受单次连接。
3. **逐项成熟度复核（已完成）**
   263 个非稳定入口均记录本体、独立样例、测试和文档直接引用证据，并逐项决定保持实验；
   即使四类静态证据齐全，也因真实网络或第二独立消费者证据不足而不批量提升。
4. **发布归档（已完成）**
   命令、日志、样本版本、原存档哈希和未关闭风险记录在
   `docs/addon-datapack-release-evidence-2026-07-27.md`，不用主观百分比替代证据。

2026-07-27 的真实图形客户端已完成首次连接、强制断线和重连；对应专服日志已通过
`network-world` 验证。若未来环境再次无法取得主显示器，仍不得用自动化测试冒充这项证据。

## 15. 最终完成定义

规划真正完成时必须同时成立：

- 主要游戏系统都有强类型、可组合、可诊断的扩展路径；
- 地图、内容、角色、活动和高频玩法各有独立纵向样本；
- 任意已有食物能通过数据获得 Stardew 风格效果；
- 多附属冲突具有稳定顺序和可读解释；
- reload 不发布半套数据，也不扩大无关目录故障；
- 内容暂时缺失不清除状态；
- 客户端不能伪造价格、库存、奖励、进度或世界修改；
- 缺少客户端资源不会隐藏或破坏服务端玩法；
- 稳定 API 演进不破坏已有二进制、数据、网络和存档；
- 新档、用户旧档副本、保存重载、专服、联网与重连都是发布门禁；
- 没有扩展时，本体行为与旧版本等价；
- 常见扩展不再依赖本体私有字段、固定坐标、菜单位置或内部实现类。

平台的完成标志不是“接口足够多”，而是未来未知的附属能用少量稳定协议完成真实玩法，同时
本体、旧档和多人服务器仍然可靠。
