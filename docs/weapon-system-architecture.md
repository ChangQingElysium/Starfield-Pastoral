# StardewCraft 武器系统逻辑架构

## 1. 边界

这份文档只约束武器定义、普通攻击、技能执行、伤害、冷却和运行时状态。

- 武器技能均为 StardewCraft 原创，不从《星露谷物语》虚构技能参考。
- 普通武器属性、暴击、防御、击退和战斗节奏继续尊重《星露谷物语》的核心语义。
- 非 Stardew 维度使用同一套武器伤害逻辑，不恢复 `5:1` 映射。
- 动作与特效暂时冻结，不作为本阶段的迁移内容。
- 不以实机启动作为验收方式；当前使用代码契约测试与编译验证。

## 2. 审计结论

当前最主要的问题不是单个技能写得长，而是系统没有唯一职责边界：

1. `StardewWeaponItem`、`StardewDaggerItem`、`StardewClubItem` 和
   `WeaponCombatEvents` 合计超过 11,000 行。
2. 剑和匕首物品类各自维护相同的 57 个技能 ID 分支，大量逻辑是复制实现。
3. 技能可能依次经过公共调度器、物品内部分支、独立 Tracker 和战斗事件；
   谁负责验证、扣冷却、选目标、结算伤害并不统一。
4. `combat/skill` 顶层存在 50 个 Tracker 文件。运行时状态分散后，退出、
   换武器、死亡、维度切换和技能打断都容易遗漏清理。
5. 当前技能路径中有 115 处服务端冷却检查和 115 处冷却写入，失败反馈和
   冷却开始时机由每个分支自行决定。
6. 技能与战斗相关代码中有 27 处直接 `hurt`，其中 26 处用 `1.0F` 作为
   哨兵伤害以触发其他事件补算。这个约定不可见，也容易被其他伤害来源误用。
7. 武器静态定义、Minecraft Attribute 和 ItemStack 战斗组件原本分别投影，
   三种物品类各复制一份，存在数值漂移风险。

## 3. 目标职责

### 3.1 武器定义

`WeaponRegistry` 是内置武器静态定义的唯一来源。定义必须在注册时满足：

- 武器 ID 唯一；
- 伤害区间合法；
- 暴击率、暴击倍率和重量是有效数值；
- 技能 ID 可以转换为规范的 `ResourceLocation`；
- 技能伤害比例与冷却不为负数。

路径形式的内置技能 ID（如 `crescent_slash`）在运行时统一解析为
`stardewcraft:crescent_slash`。带命名空间的附属技能 ID 保持原样。

### 3.2 物品投影

`WeaponItemSupport` 负责把一份 `WeaponData` 投影为：

- Minecraft 主手攻击伤害；
- Minecraft 攻速；
- 实体交互距离；
- ItemStack 上的 `WeaponStats`；
- 锻造数据初始化。

剑、匕首和棍棒不得再各自复制这套公式。

### 3.3 技能入口

所有按键请求只进入 `WeaponSkillDispatcher` 一次：

1. 服务端从玩家当前手中完整 ItemStack 重新解析技能；
2. Stack-aware 公共装备定义优先，允许附属有意覆盖；
3. 没有公共定义时，读取内置 `IStardewWeapon` 的 `WeaponData`；
4. 找到注册 Handler 时交给 Handler；
5. Handler 不存在或明确返回 `PASS` 时才进入旧物品实现。

旧物品实现不得再次查询或调用公共 Handler，避免双重调度。

### 3.4 技能运行时

最终每个技能 Handler 应拥有相同的服务端生命周期：

`validate -> begin -> tick -> finish`

其中：

- `validate`：检查冷却、资源、姿态冲突和前置目标，但不产生副作用；
- `begin`：创建唯一执行实例，冻结必要快照，决定冷却承诺；
- `tick`：只推进该实例，不从全局猜测技能上下文；
- `finish`：以完成、打断、失效、玩家离线等明确原因收尾并清理。

技能的原创机制和既有数值在迁移时保持不变。一次只迁移一个可验证链路。

每次执行在 `begin` 时冻结 `WeaponDamageSnapshot`。即时命中、延迟
Tracker、投射物、DOT、范围伤害和后续派生伤害必须继承这份快照：

- 玩家在技能飞行或延迟期间换武器，不改变该次执行的伤害、暴击、附魔和
  武器专属规则；
- 父技能结束后仍存活的投射物或 DOT 自己持有快照；
- 派生技能 ID 使用显式快照绑定，不能靠当前手持武器或猜测父 Runtime；
- 投射物跨保存/加载时同时持久化武器 ID 与完整 ItemStack；
- 未被伤害事件消费的 pending context 必须在 `finally` 中回收。

### 3.5 伤害

普通攻击从 Minecraft `player.attack` 进入统一的 Stardew
`DamagePipeline`。技能命中统一调用服务端 `WeaponSkillDamage`，携带：

- 施法者、武器和技能 ID；
- 目标；
- 武器伤害快照或明确的基础值；
- 技能伤害倍率；
- 是否允许暴击、击退和职业修正；
- 命中时是否重新检查可取消的攻击许可事件。

`WeaponSkillDamage` 绑定技能上下文和释放武器快照，再进入唯一的
`WeaponCombatEvents -> DamageCalculator -> DamagePipeline`。传给其他伤害
监听器的是基于释放武器与技能倍率的有效预减伤输入，不再使用
`hurt(..., 1.0F)` 暗示“真正伤害稍后补算”。

即时技能默认使用 `SKILL_DAMAGE`，不会把一次技能命中伪装成新的玩家输入。
原实现确实会在延迟命中时重新经过可取消攻击事件的技能，显式使用
`RESPECT_AT_IMPACT`，并遵守“先绑定上下文、再检查许可、最后伤害和清理”的
顺序。

### 3.6 跨维度生命结算

武器治疗、吸血和非致命生命消耗统一经过 `CombatHealing`：

- Stardew 维度读写 Stardew 自定义生命；
- 其他维度读写 Minecraft 原生生命；
- 数值保持 `1:1`，不引入维度倍率；
- 百分比治疗和生命消耗必须使用当前维度的权威最大/当前生命；
- 技能资源、状态和属性不能因为离开 Stardew 维度而静默失效。

## 5. 每个技能的迁移验收

一个技能只有同时满足以下条件才算迁移完成：

- 注册定义、运行时 Handler 和技能 ID 一一对应；
- 客户端请求不能决定命中、伤害或冷却；
- 冷却只提交一次，失败不误扣；
- 目标选择和伤害结算均为服务端权威；
- 完成与所有中断路径都能清理状态；
- 不依赖 `1.0F` 哨兵伤害；
- 原创机制、数值和触发条件没有被擅自重设计；
- 相关契约测试和 `gradle classes` 通过。
