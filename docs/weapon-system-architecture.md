# StardewCraft 武器系统逻辑架构

## 1. 边界

这份文档只约束武器定义、普通攻击、技能执行、伤害、冷却和运行时状态。

- 武器技能均为 StardewCraft 原创，不从《星露谷物语》虚构技能参考。
- 普通武器属性、暴击、防御、击退和战斗节奏继续尊重《星露谷物语》的核心语义。
- 非 Stardew 维度使用同一套武器伤害逻辑，不恢复 `5:1` 映射。
- 动作与特效暂时冻结，不作为本阶段的迁移内容。
- 不以实机启动作为验收方式；当前使用代码契约测试与编译验证。

## 2. 重构前审计基线

本节数据用于说明这次重构为什么发生，是迁移开始前的历史快照，不是
当前工作树仍然存在的数量。当前逻辑边界与已完成迁移以第 3、4 节为准。

当前最主要的问题不是单个技能写得长，而是系统没有唯一职责边界：

1. `StardewWeaponItem`、`StardewDaggerItem`、`StardewClubItem` 和
   `WeaponCombatEvents` 合计超过 11,000 行。
2. 剑和匕首物品类各自维护相同的 57 个技能 ID 分支，大量逻辑是复制实现。
3. 技能可能依次经过公共调度器、物品内部分支、独立 Tracker 和战斗事件；
   谁负责验证、扣冷却、选目标、结算伤害并不统一。
4. `combat/skill` 顶层存在 50 个 Tracker 文件。运行时状态分散后，退出、
   换武器、死亡、维度切换和技能打断都容易遗漏清理。
5. 当前技能路径中有 115 处服务端冷却检查和 115 处冷却写入，失败反馈和
   冷却开始时机由每个分支自行决定。
6. 技能与战斗相关代码中有 27 处直接 `hurt`，其中 26 处用 `1.0F` 作为
   哨兵伤害以触发其他事件补算。这个约定不可见，也容易被其他伤害来源误用。
7. 武器静态定义、Minecraft Attribute 和 ItemStack 战斗组件原本分别投影，
   三种物品类各复制一份，存在数值漂移风险。

## 3. 目标职责

### 3.1 武器定义

`WeaponRegistry` 是内置武器静态定义的唯一来源。定义必须在注册时满足：

- 武器 ID 唯一；
- 伤害区间合法；
- 暴击率、暴击倍率和重量是有效数值；
- 技能 ID 可以转换为规范的 `ResourceLocation`；
- 技能伤害比例与冷却不为负数。

内置武器的权威链只有一条：

`WeaponRegistry` Java 模板 -> 版本化 ItemStack `WeaponStats` -> 锻造派生数值。

基础平衡改动如果需要刷新已存在武器，必须同步提升
`WeaponStats.CURRENT_DATA_VERSION`；不再建立一份 JSON 基础定义。表现配置
以规范技能 ID 另行索引，不得反向成为伤害或运行时逻辑的
权威来源。

路径形式的内置技能 ID（如 `crescent_slash`）在运行时统一解析为
`stardewcraft:crescent_slash`。带命名空间的附属技能 ID 保持原样。

### 3.2 物品投影

`WeaponItemSupport` 负责把一份 `WeaponData` 投影为：

- Minecraft 主手攻击伤害；
- Minecraft 攻速；
- 实体交互距离；
- ItemStack 上的 `WeaponStats`；
- 锻造数据初始化。

剑、匕首和棍棒不得再各自复制这套公式。

### 3.3 技能入口

所有按键请求只进入 `WeaponSkillDispatcher` 一次：

1. 服务端从玩家当前手中完整 ItemStack 重新解析技能；
2. Stack-aware 公共装备定义优先，允许附属有意覆盖；
3. 没有公共定义时，读取内置 `IStardewWeapon` 的 `WeaponData`；
4. 找到注册 Handler 时交给 Handler；
5. Handler 不存在或明确返回 `PASS` 时才进入旧物品实现。

旧物品实现不得再次查询或调用公共 Handler，避免双重调度。

### 3.4 技能运行时

最终每个技能 Handler 应拥有相同的服务端生命周期：

`validate -> prepare(begin) -> commit -> committed effects -> tick -> finish`

其中：

- `validate`：检查冷却、资源、姿态冲突和前置目标，但不产生副作用；
- `prepare(begin)`：创建唯一执行实例，冻结必要快照，预留可精确
  撤销的资源和状态；禁止在此阶段伤害或移动目标、传送施法者、
  生成实体或执行其他不可逆效果；
- `commit`：由 Runtime 唯一执行，关闭失败补偿窗口并确认能量、状态
  与冷却承诺；
- `committed effects`：提交后才执行伤害、位移、生成和呈现。此阶段
  异常会使执行失效并统一收尾，但不得退回已提交资源、冷却，也
  不得向客户端伪报“施法被拒绝”；
- `tick`：只推进该实例，不从全局猜测技能上下文；
- `finish`：以完成、打断、失效、玩家离线等明确原因收尾并清理。

技能的原创机制和既有数值在迁移时保持不变。一次只迁移一个可验证链路。

每次执行在 `begin` 时冻结 `WeaponDamageSnapshot`。即时命中、延迟
Tracker、投射物、DOT、范围伤害和后续派生伤害必须继承这份快照：

- 玩家在技能飞行或延迟期间换武器，不改变该次执行的伤害、暴击、附魔和
  武器专属规则；
- 父技能结束后仍存活的投射物或 DOT 自己持有快照；
- 派生技能 ID 使用显式快照绑定，不能靠当前手持武器或猜测父 Runtime；
- 投射物跨保存/加载时同时持久化武器 ID 与完整 ItemStack；
- 未被伤害事件消费的 pending context 必须在 `finally` 中回收。

### 3.5 伤害

普通攻击从 Minecraft `player.attack` 进入统一的 Stardew
`DamagePipeline`。技能命中统一调用服务端 `WeaponSkillDamage`，携带：

- 施法者、武器和技能 ID；
- 目标；
- 武器伤害快照或明确的基础值；
- 技能伤害倍率；
- 是否允许暴击、击退和职业修正；
- 命中时是否重新检查可取消的攻击许可事件。

`WeaponSkillDamage` 绑定技能上下文和释放武器快照，再进入唯一的
`WeaponCombatEvents -> DamageCalculator -> DamagePipeline`。传给其他伤害
监听器的是基于释放武器与技能倍率的有效预减伤输入，不再使用
`hurt(..., 1.0F)` 暗示“真正伤害稍后补算”。

普通主目标攻击用稳定的武器平均值作为 `hurt` 的非零运输触发值，
不接受 Minecraft `attackStrength` 的蓄力缩放；它不再参与任何防御数学。
原生 sweep 不再产生 Stardew 武器伤害；朝向范围内的每个次目标由
共享 Stardew 伤害入口独立结算。
外维 Incoming 在盾牌、无敌帧和护甲之前将其替换为 `DamagePipeline`
唯一生成的随机、技能、暴击与职业结果；Stardew 目标则在自己的权威
防御边界结算一次。

暴击强度区分两种原版语义：

- 武器与翡翠锻造使用 Crit. Power 点数，基础暴击倍率为
  `3 + points / 50`；
- 先天暴击强度与公共 API `crit_power` 使用相对倍率，
  `0.5` 表示 `+50%`；
- Desperado 只在该次攻击确实暴击时乘二，普通命中不受影响。

每次同步 `hurt` 调用拥有独立伤害帧：外维 Incoming 到 Pre 使用同一个
`DamageContainer` 实例精确领取，Pre 到 Post 再以目标与
`DamageSource` 实例做 LIFO 匹配。`hurt()` 的布尔返回值只说明
Minecraft 接受了这次调用，不代表最终造成了正生命伤害，也不得用于
发奖励、上状态、续连段或播放命中成功反馈；因此生产入口已经改为
`void`，这些玩法结果只能消费精确 Applied Post 帧。旧
`Result/ResultCapture` 旁路已删除。同步派生伤害不能
覆盖外层技能 ID、暴击或释放武器。默认击退强度在 Pre 计算，只在精确 Post 确认最终生命
伤害大于零时执行；`Player.attack` 中的原生主目标/扫击击退被关闭，
因此一次命中只有一个击退所有者。

每个生产技能伤害必须显式声明两条互相正交的策略：

- `AttackGatePolicy`：独立物理攻击使用 `RESPECT_AT_IMPACT`，在命中时
  重放可取消攻击许可；父命中派生的 DOT、爆炸、领域和后续伤害使用
  `SKILL_DAMAGE`，不伪装成新的玩家输入；
- `HitCooldownPolicy`：默认 `RESPECT_VANILLA`；只有作者明确设计为可在同一
  原版受击冷却窗口内连续命中的序列使用
  `BYPASS_FOR_AUTHORED_SEQUENCE`。绕过通过仅增加
  `BYPASSES_COOLDOWN` 标签的伤害源完成，禁止清零目标的
  `invulnerableTime` 或 `hurtTime`。木乃伊复活的四处清零属于实体状态转换，
  是当前唯一白名单，不是技能命中实现。

所有 `RESPECT_AT_IMPACT` 路径遵守“先绑定上下文、再检查许可、最后伤害和
清理”的顺序。

### 3.6 跨维度生命结算

武器治疗、吸血和非致命生命消耗统一经过 `CombatHealing`：

- Stardew 维度读写 Stardew 自定义生命；
- 其他维度读写 Minecraft 原生生命；
- 数值保持 `1:1`，不引入维度倍率；
- 永久最大生命成长例外地按既有 `100:20` 生命池比例投影到
  Minecraft `MAX_HEALTH`；这不影响武器伤害的 `1:1` 规则；
- 百分比治疗和生命消耗必须使用当前维度的权威最大/当前生命；
- 技能资源、状态和属性不能因为离开 Stardew 维度而静默失效。
- 吸血等装备恢复也必须走 `CombatHealing`；仙女盒仅按原生护甲结算后
  的最终伤害累计。
- 每日幸运投影前先经过日期惰性刷新；免疫与坚固只处理
  `MobEffectCategory.HARMFUL`，不将 `NEUTRAL` 误判为负面效果；连续燃烧
  由独立点燃状态机结算。
- Stardew 武器在外维度不再把 Minecraft 护甲点数另当作 Stardew
  韧性重复减算，也不再用静态运输值计算保护比例。唯一权威武器伤害在
  NeoForge Incoming 写入，之后原生盾牌、无敌帧、护甲/韧性、Protection、
  Resistance、吸收和护甲耐久自然处理该数值；Post 的真实生命损失是
  Applied 唯一事实。Stardew 维度仍使用原版固定韧性语义。
- 装备攻击、临时攻击与战士/野蛮人职业只在原生武器路径投影为
  Minecraft `ATTACK_DAMAGE`；持有 Stardew 武器时由统一伤害管线结算，
  不允许膨胀原生输入后再间接改变护甲/韧性比例。原生近战同时映射
  侦察兵暴击率、亡命徒暴击伤害和暴击祝福，Stardew 武器仍只算一次。
- 外维原生攻击与受击都在权威事件入口即时同步当前装备属性，避免换装后的
  第一击沿用上一 tick。钢脊与地脉堡垒读取 Post 的真实生命损失；钢脊按
  `1:1` 伤害单位蓄能，不套用仅供 100:20 生命池显示的比例。
- 生命、最大生命、能量、最大能量与疲惫状态使用独立轻量
  vitals 包。一次受击或回复不得连带发送完整 PlayerData 与装备包；
  SavedData 持久化、完整客户端同步和 vitals 同步分别持有自己的
  dirty 边界，网络发送不能提前清掉存档脏标记。

## 5. 每个技能的迁移验收

一个技能只有同时满足以下条件才算迁移完成：

- 注册定义、运行时 Handler 和技能 ID 一一对应；
- 客户端请求不能决定命中、伤害或冷却；
- 冷却只提交一次，失败不误扣；
- 目标选择和伤害结算均为服务端权威；
- 完成与所有中断路径都能清理状态；
- begin 期间创建的外部状态在后续启动步骤失败时能按精确所有者回收；
- 不依赖 `1.0F` 哨兵伤害；
- 原创机制、数值和触发条件没有被擅自重设计；
- 相关契约测试和 `gradle classes` 通过。

当前 prepare 边界由运行时两阶段机制与源码契约双重锁定。源码契约
使用 JDK AST 解析实际符号，以 `owner#method(erased parameters)` 精确
签名维护默认拒绝白名单；构造器、非局部写入、普通方法引用和同 Handler
辅助方法都会纳入递归审计。只有直接登记给 committed effect 或 begin
失败补偿的回调才构成延迟边界。新增、删除或无法解析的 prepare 操作都会
使契约失败，旧字符串禁用清单继续作为第二层防线。
