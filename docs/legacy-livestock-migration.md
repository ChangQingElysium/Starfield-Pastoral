# 旧动物存档迁移

## 问题与入口

动物日结已经切换至 `LivestockService`，但旧存档仍将动物保存在
`data/stardew_animal_world.dat`。旧实体等待旧日结时间戳追上今天，因此右键会一直提示尚未准备好。

`LegacyLivestockMigration` 在服务端启动、动物恢复流程和管理方块交互时自动导入。
无需玩家删除动物、重新购买或重新建造住所。旧实体进入已加载区块时根据迁移记录淘汰，
由当前动物系统恢复实体；不为清理旧实体强制加载整个世界。

## 存储与重试

- `stardew_livestock_migration.dat`：保留旧文件 `data` 下的完整原始 NBT，以及未解决条目的 `Issues`。
  导入器不覆盖旧文件；原始快照不经过会裁剪干草或丢弃未知字段的旧世界数据加载器。
- `stardew_buildings.dat`：每个旧建筑 ID 对应的 UUID、建筑记录一并保存。
- `stardew_livestock.dat`：动物、产物、待命名幼崽、干草及各自导入标记一并保存。

先用可报告失败的同步原子写入保存原始快照，再保存两个目标账本，最后清理旧实体。
NeoForge 的常规 `SavedData.save` 会异步排队并吞掉写入异常，不能充当迁移的落盘确认。
迁移检查点先等待已有写入结束，再调用 `IOUtilities.writeNbtCompressed`，成功后才清除脏标记。

导入标记在出售动物、领取产物、拆除建筑、删除农场后仍保留。
重进存档时以目标账本的标记决定是否补导入，不以第三个文件的“已完成”字段跳过恢复。
已经在新系统改名、换住所或出售的动物不会被旧快照覆盖或重新生成。
缺少主人农场、维度未加载或建筑占地冲突的条目保留原始数据，并以 `[ANIMAL_MIGRATION]` 输出原因；
未解决时每 100 tick 最多重试一次，仅在原因变化时记录日志。

## 字段与异常情况

| 旧数据 | 新系统处理 |
| --- | --- |
| 已付费建筑等级 | 接入为当前等级的自建建筑，不重放建造流程，不替换原来的方块。设施不足时保留等级并显示需要补齐设施。 |
| 同坐标已有同农场、同种类的新住所 | 复用现有记录，保留新住所的等级、门和喂食状态。不同归属或占地冲突不覆盖。 |
| 住所消失 | 动物进入管理列表的“待安置”状态；不日结扣状态。重新安置后从当天继续，滞留产物跟随安置。 |
| 名称、物种、年龄、饲养天数、好感、心情、饱食度、抚摸状态 | 保留；迁移当天作为新日结起点，不补算停摆期间的损失或产物。 |
| 待收获产物、品质、产出间隔、金色动物饼干、繁殖开关 | 保留。旧 `cow` 对应 `white_cow`；未知扩展物种保持原 ID，不替换为默认鸡。 |
| 扩展状态及未知字段 | 原始动物 NBT 保存在 `Extra.LegacyAnimal`；`addonData` 接入新扩展数据字段。 |
| 地面产物账本 | 每条旧产物导入一次。旧区块后来载入时，已收取产物不会从旧方块再次出现。 |
| 更早版本无账本的产物方块 | 按维度、坐标和旧动物编号去重，保留 ItemStack 数据，先落盘后清除旧方块。 |
| 待命名出生事件 | 接入正常幼崽命名流程并占用床位。 |
| 干草 | 累加一次，超过目前筒仓容量的余额也保留并可取用。 |
| 旧孵化器 | 读取旧小写 NBT 字段，将 1260 分钟旧日历按原完成时刻（第几天、几点）换算到统一的 1600 分钟机器时钟，保留已完成状态；旧蛋保持白天到点即可孵出，新放入的蛋按原版只在过夜时完成。 |

旧孵化器的稳定标记包含农场 UUID、维度、坐标、旧完成时间及蛋的物品 ID。
农场槽位复用不会消耗另一座农场的蛋；已经孵化并出售的幼崽不会因旧孵化器区块再次载入而复活。
找不到归属时继续保留旧输入，等待可确定农场后转换。

## 验证与实际存档验收

定向测试位于 `LegacyLivestockMigrationGameTests`，覆盖字段保留、原始快照不变、新旧数据混存、
两个目标文件分别缺失时补导入、改名换住所及出售后重放、重复领取、未知物种、建筑缺失及占地冲突、
旧实体回载、无账本产物落盘、失去住所后日结暂停及重新安置、旧孵化倒计时与售后防重复。

```sh
./gradlew classes checkTranslations
./gradlew runGameTestServer -PgameTestNamespaces=stardewcraft_livestock
```

本次验证：Java 编译、12 种语言一致性检查通过；动物系统 29 项必需 GameTest 全部通过，
其中 7 项为本次旧存档迁移回归测试。

自动化使用构造的旧 NBT 和无界面游戏测试，不能代替用户实际旧存档的验收。
实际存档应检查：进世界后动物数量与名称、右键管理和抚摸、跨天状态、旧蛋与干草余额、未完成孵化倒计时，
以及换住所/出售/收取后退出重进是否保持一致。缺失住所的动物应能从管理列表重新安置。
如果旧版本已经把某条数据清空并保存，迁移器只能保留当前能读取到的数据，恢复缺失内容需要更早的存档备份。
